# Work Timer 크롬 확장 (팝업)

툴바 팝업에서 로그인·회원가입하고, 진행 중인 작업을 보고 일시정지·다시 시작·종료·저장(업무 결과 입력)합니다.
타이머 화면의 작업 폼은 웹앱과 같습니다(작업명, 업무 내용/결과, 목표 시간, 소요 시간 직접 입력, 측정 시작·기록 저장).
팝업 상단 막대에서 타이머·일지·메모·요약 화면으로 이동합니다. 우측 상단 설정(톱니) 버튼 메뉴에서 다크·라이트 모드 전환, 웹페이지 방문(웹앱을 새 탭으로 열기), 고급(창에서 아래 두 항목을 고른다), 로그아웃을 합니다. 고급 창에서는 AI 연결(Claude·Codex·연결된 앱 중 고르면 그 항목의 안내 창이 열린다. 연결된 앱에서는 연결 해제), 계정 설정(현재 비밀번호 확인 후 비밀번호 변경·데이터 삭제·계정 삭제)을 하고, 팝업을 열 때 처음 보일 화면(기본은 마지막으로 본 화면, 또는 타이머·일지·메모·요약)과 Ctrl+Enter 빠른 확인(기록 폼의 측정 시작·수정 저장, 종료 창의 종료하고 저장) 사용 여부를 고릅니다(테마는 처음엔 브라우저 설정을 따릅니다).
일지 화면에서는 날짜를 옮기거나 작업 캘린더에서 고른 날짜의 기록을 보고, 완료 기록을 수정(타이머 화면 폼으로 이동)하거나 삭제합니다. 일지 화면 위의 "일일 메모"를 누르면 그 날짜의 일일 메모를 봅니다. 요약은 일지에서 고른 날짜의 측정 시간과 하루 활동 시계를 보여 주고, "CSV" 버튼으로 기간을 골라 업무 기록을 CSV 파일로 내보내거나 같은 범위의 AI 요약 프롬프트를 복사합니다(웹앱 통계의 데이터 내보내기와 같습니다).
메모 화면(메모장)과 일일 메모는 웹앱과 같이 추가, 제목·내용 수정(자동 저장), 위·아래 이동, 삭제를 할 수 있습니다. 메모장은 접기·펼치기도 됩니다.
빌드 단계 없이 이 폴더를 그대로 크롬에 불러옵니다.

## 설치 (개발용)

1. 확장은 Vercel 서버(`https://work-timer-mauve-seven.vercel.app`)에 연결합니다.
2. 크롬에서 `chrome://extensions`를 열고 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 눌러 이 `extension/` 폴더를 고릅니다.
4. 카드에 표시된 확장 ID를 Vercel 프로젝트 환경 변수에 넣고 다시 배포합니다.

   ```
   EXTENSION_ORIGIN="chrome-extension://<확장 ID>"
   ```

5. 팝업을 열어 로그인하거나 회원가입합니다. 팝업과 사이트는 같은 로그인 쿠키를 씁니다(사이트에서 로그인해 두어도 됩니다).
   팝업 로그인·메모·계정 기능에는 서버가 확장 Origin의 쓰기 요청을 허용해야 합니다(웹앱 `trustedOrigin`).

## 다른 서버에 연결

`config.js`의 `APP_ORIGIN`과 `manifest.json`의 `host_permissions`를 같은 주소로 바꾸고, 그 서버의 `EXTENSION_ORIGIN`에 확장 ID를 설정합니다.
확장 ID는 폴더 경로가 같으면 유지됩니다.

## Chrome 웹 스토어에 배포한다면 해야 할 일

아직 배포하지 않았다. 배포할 때 아래 순서로 진행한다. 등록비와 절차는 정리한 시점(2026-10) 기준이라 실제 화면과 다를 수 있다.
구글 플레이(안드로이드 앱) 개발자 등록과는 별개이며, 확장만 게시한다면 플레이 등록은 필요 없다.

### 1. 개발자 등록 (직접)
- [ ] Chrome Web Store 개발자 대시보드(`chrome.google.com/webstore/devconsole`)에 게시자로 쓸 구글 계정으로 로그인
- [ ] 개발자 계약 동의, 등록비 5달러(1회) 결제
- [ ] 게시자 이름·연락 이메일 입력과 이메일 인증(공개 게시라 스토어에 표시됨)

### 2. 제출물 준비 (코드)
- [x] 개인정보처리방침 페이지: 웹앱에 `/privacy` 추가(`dev` PR → `main` 병합 → 운영 배포. 운영 반영은 병합 후 확인). 저장하는 데이터(계정, 업무 기록, 메모), 로그인 쿠키, 확장이 서버와 주고받는 내용을 적는다
- [x] 아이콘: `manifest.json`에 16·48·128px PNG(`icons`, `action.default_icon`) 지정
- [x] `manifest.json`: `version` 확인, `description`을 스토어 설명과 맞춤, `host_permissions`는 운영 주소 하나만
- [x] 제출용 zip: `extension/` 폴더 안의 파일만 압축(`.md` 제외)
- [x] 스토어 문구 정리([STORE.md](STORE.md)): 상세 설명, 단일 목적("업무 타이머·기록 조회와 조작"), 권한별 사용 이유(운영 사이트 접근 = 기록 조회·저장), 원격 코드 사용 없음, 수집 데이터 항목

### 3. 이미지 (직접 또는 함께)
- [ ] 스크린샷 1280×800 1장 이상(로그인한 팝업에 진행 작업이 보이는 화면)
- [ ] 작은 홍보 타일 440×280(선택, 공개 게시면 권장)

### 4. 업로드와 등록정보 작성 (직접)
- [ ] 대시보드 "새 항목"에서 zip 업로드
- [ ] 스토어 등록정보: 설명, 카테고리(생산성), 언어(한국어), 아이콘·스크린샷
- [ ] 개인정보 보호 탭: 단일 목적, 권한 사용 이유, 원격 코드 "아니요", 수집 데이터 체크, 개인정보처리방침 URL
- [ ] 배포 탭: 공개, 지역

### 5. 확장 ID를 서버에 연결 (직접, 심사 제출 전에)
- [ ] 업로드 직후 대시보드에 표시되는 스토어 확장 ID 확인
- [ ] Vercel 환경 변수 `EXTENSION_ORIGIN="chrome-extension://<스토어 ID>"` 설정 후 운영 재배포
  (빠뜨리면 조회는 되지만 저장·조작에서 "허용되지 않은 요청입니다"가 난다. 서버는 ID 하나만 받으므로, 개발용 확장을 계속 운영 서버에 붙이려면 아래 7번의 `key`로 ID를 맞추거나 서버가 여러 ID를 받도록 고친다)
- [ ] 심사관용 테스트 계정 준비(로그인이 필요한 기능이라 요청받을 수 있음)

### 6. 심사 제출
- [ ] "검토를 위해 제출". 보통 며칠, 첫 게시·사이트 권한이 있으면 더 걸릴 수 있다
- [ ] 흔한 반려 사유 점검: 설명과 실제 기능 불일치, 권한 사용 이유 누락, 개인정보처리방침 없음·부실

### 7. 게시 후
- [ ] 스토어에서 설치해 운영 서버로 동작 확인
- [ ] 업데이트할 때는 `manifest.json`의 `version`을 올리고 zip을 다시 올린다(재심사)
- [ ] (선택) 대시보드의 공개 키를 개발용 `manifest.json`의 `key`에 넣으면 압축해제 로드한 개발용 확장도 스토어와 같은 ID를 쓴다
